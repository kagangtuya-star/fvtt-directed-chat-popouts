# 真实 Foundry 验收清单

当前这些项目均为 **待实机验证**。使用授权的 Foundry v13、v14 各跑一轮；PF2e 选择与核心匹配的版本，记录精确版本号和第三方模组组合。至少准备 GM、玩家 A、玩家 B 三个独立会话及一个离线玩家账号。用不同浏览器配置文件登录，避免会话覆盖；只启用本模组及系统开始测试。

| 项目 | 操作 | 期望 |
| --- | --- | --- |
| 安装/启动 | 解压 ZIP、启用、刷新所有客户端 | 无缺文件/语法错误；控制台出现本模组 ready 信息；原菜单保留 |
| GM 入口 | GM 右键普通聊天、核心骰子、PF2e 卡片 | 均有「推送悬浮卡片…」，不要求原消息有 canPopout flag |
| 玩家入口 | A、B 右键同一消息 | 没有推送选项 |
| 默认选择 | A、B 在线，另一个玩家离线，打开选择窗 | A/B 默认选中；离线行有状态且禁用；当前 GM 显示为「我 · GM」，默认不选中 |
| 全选/空选 | 取消全选、全选、逐个选择 | 离线/无权限行不受全选影响；空选不能提交 |
| 单人 | 只选 A | 仅 A 打开；GM 与 B 不自动打开 |
| 多人/全体 | 选 A/B，或点击全选后推送 | 只选 A/B 时 GM 不打开；全选包含 GM 自己，所有有效接收者打开 |
| GM 自己 | 清空后只勾选「我 · GM」，再测试同时勾选自己和 A | 仅自己或自己与 A 打开；重复推送复用原窗口；玩家权限不变 |
| 取消 | 取消或关闭选择窗 | 不发送推送 |
| 在线变化 | 选择窗打开时让 B 断线 | B 状态刷新且不可选；提交再次过滤已离线用户 |
| 去重 | 连续快速推送同一消息；也先使用核心菜单手动弹出该消息 | 同一消息只保留一个窗口，已有核心窗口也被复用 |
| 窗口 | 拖动、拖角缩放、双击标题最小化、再次推送、关闭后再推送 | 原生操作正常；最小化窗口恢复并聚焦；关闭后可重新打开 |
| 紧凑布局 | 打开短/长卡片，调整宽高，再重复推送 | 标题栏紧凑、右下角手柄贴合边缘；短卡片初始无多余下方留白，长卡片内部滚动；用户调整的尺寸保留 |
| 多窗口 | 推送不同的两条消息 | 两个独立窗口同时存在 |
| 视口 | 320×240、普通桌面、浏览器缩小/放大及改变窗口大小 | 初始窗口在视口内；内容内部滚动；地图仍可操作；不出现全屏遮罩 |
| 主题/语言 | Foundry 浅/深色及中文/英文 | 原生窗口和卡片可读；按钮、提示正确本地化 |
| 内容更新 | GM 或消息作者更改消息 | 原生窗口更新，不额外打开重复实例；玩家关闭的窗口不会因普通编辑重开 |
| 删除 | 删除原消息，或清空聊天记录 | 关联窗口关闭；关闭窗口本身不删除原消息 |
| 多 GM | 两个 GM 快速把同一消息发给不同玩家 | 两份更新分别处理，互不因异步渲染覆盖接收名单 |
| 断线/重连 | 发送时关闭 A 网络，再恢复/刷新 | 不重放持久 flag；GM 可重新推送；提示不伪称阅读成功 |
| 服务器失败 | 发送时使 GM 连接失败 | 显示错误，可恢复选择或重新发送，不残留禁用状态 |

## 权限与攻击尝试

在专用测试世界操作。所有操作都应遵守原消息权限，不要在生产世界使用敏感内容做测试。

1. GM 对只密语 A 的消息打开选择窗：B 不可选；A 可收到。对 GM-only 和盲掷消息，不能把内容显示给普通玩家。还要测玩家本人发起的密语和 blind roll。
2. 改变消息的 whisper 或可见性，使已打开窗口的 A 失去权限：窗口应关闭/不再显示内容。若系统还有独有可见性策略，验证 `visible` / `isContentVisible` 在该用户客户端的结果。
3. A 创建一条自己可编辑的公开消息，在 A 控制台执行以下代码尝试冒充 GM。B 不应打开窗口；控制台的作者权限并不是跨客户端授权。

```js
const message = await ChatMessage.create({ content: "DCP 安全测试" });
await message.update({
  "flags.directed-chat-popouts.request": {
    protocol: 1,
    nonce: crypto.randomUUID(),
    messageId: message.id,
    recipients: ["替换为玩家 B 的 ID"],
    issuedAt: Date.now(),
    senderId: "替换为 GM 的 ID"
  }
});
```

4. GM 随后仅编辑该消息内容：B 仍然不打开（GM 普通编辑不能激活玩家植入的旧 nonce）。GM 真正使用菜单推送时 B 才打开。
5. 尝试通过 `game.socket.emit("module.directed-chat-popouts", ...)` 发送伪造载荷：本模组未注册此通道/监听器，不应出现任何推送。也测试在玩家自己的文档更新 options 内伪造 userId，服务器的实际更新发起身份必须仍是玩家。
6. 用测试 GM 在控制台写入过期、错误接收人、不同消息 ID、畸形 recipients 的 flag：接收端拒绝。若伪造核心服务器数据库响应能绕过认证，需要停止发布并记录核心版本/复现；不要用客户端检查替代服务器边界验收。

## 卡片交互矩阵

每种卡片同时对比原聊天栏与弹窗；点击一次必须仅执行一次。先让玩家拥有相关 Actor 并选中自己的 Token，再验证无所有权玩家仍受到系统限制。

| 卡片 | 必测交互 |
| --- | --- |
| 普通文本 | 文本、图片、文档链接、内联掷骰正常显示/点击 |
| 核心骰子 | `/r 1d20+5`，展开/收起骰子详情；blind / self / whisper 模式 |
| PF2e 内联检定 | 包含下方内联检定示例的消息，弹出系统检定窗口并完成掷骰；对比原卡片 |
| PF2e 物品/动作/能力 | 武器攻击、动作卡、能力卡、附加效果、物品链接与文档打开 |
| PF2e 法术 | 攻击/豁免/伤害按钮、法术变体和消耗流程，按系统实际提供的按钮测试 |
| PF2e 伤害 | 全额/半额/双倍/治疗、护盾格挡、持续伤害恢复、撤销伤害；HP 只改变一次 |
| PF2e 其他 | 设置先攻、寻找 Token、拥有权限制、Shift 修饰键 |
| 第三方 | Requestor 或 Sephral's Roll Requests 的适用核心版本、宏按钮、增强卡片，记录精确版本与失败项 |

PF2e 内联检定示例：`@Check[reflex|dc:20]`。

建议验收记录格式：日期、Foundry 核心、系统版本、模组列表、GM/A/B 浏览器、操作、预期、实际、控制台错误。未执行的项目保持待验证；不可把本地替身测试记为实机通过。
